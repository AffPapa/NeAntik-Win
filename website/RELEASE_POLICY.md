# NeVision Win — политика релизов

Этот файл — постоянное правило проекта. После каждого выпуска новой версии мы обновляем:

1. `CHANGELOG.md`;
2. `app/page.tsx` — production-источник краткой истории версий на сайте;
3. номер версии на странице и, при необходимости, в установщике/portable-архиве.
4. публичные ZIP, SHA-256, release manifest и `/release.json` для скачивания.

Единый источник версии приложения — `release-version.json`. Опубликованные ZIP неизменяемы:
исправление бинарника требует новой версии. Публичный ZIP повторно скачивается и сравнивается
с локальным SHA-256; проверяется распакованный EXE, а не только исходники. Сайт публикуется
с новым changelog одновременно с проверенным выпуском. Секреты, Data, backups и логи тестов
не загружаются. Исходный репозиторий остаётся приватным до отдельного выбора лицензии.

## Формат каждой записи

Каждый релиз обязан содержать:

- **версию** в формате `MAJOR.MINOR.PATCH`;
- **дату выпуска**;
- **статус**: stable, preview, beta, hotfix или deprecated;
- **версию browser core**, если она менялась;
- блоки: `Добавлено`, `Изменено`, `Исправлено`, `Безопасность`, `Удалено` — только применимые;
- **совместимость профилей**: совместимо / нужна миграция / миграция необратима;
- **backup и rollback**: нужен ли backup, как откатиться;
- **известные проблемы**;
- **SHA-256** portable-архива или установщика для публичного бинарного релиза.

## Правила безопасности и качества

- До обновления browser core создаётся резервная копия каждого затронутого профиля.
- Нельзя объявлять версию stable без проверки запуска, создания/закрытия профиля, backup/restore и proxy connection check.
- Нельзя скрывать breaking changes: они попадают в верхнюю часть changelog и помечаются в интерфейсе обновления.
- Новые функции не должны обещать обход антифрода, банов или правил сторонних сервисов.
