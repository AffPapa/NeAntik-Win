# NeAntik Win 0.8.15-preview — ручной accessibility smoke test

Дата: 2026-10-14. Цель — проверить текущий опубликованный EXE, а не выводить
доступность из unit-тестов или скриншота. Тест использовал отдельный извлечённый
portable-каталог без прежних профилей; имя `Codex QA profile` было только
синтетическим и не сохранено.

## Идентичность и среда

- Публичный релиз: [v0.8.15-preview](https://github.com/AffPapa/NeAntik-Win/releases/tag/v0.8.15-preview).
- Бинарный source commit: `5434718dd14a5ea0edc20c440c801a873c9fbcf4`.
- Проверенный EXE SHA-256: `6392a400aea47912792ac266cf9cf9044acc7a7ec7fce0fc82cce7e94fbecef2`.
- Windows 11 x64, Tk 8.6.15 согласно текущей сборочной связке проекта.
- Перед запуском в этом extracted candidate не было `Data/` или `Profiles/`.

## Результаты

- **PASS — форма открывается:** кнопка «Новый профиль» открыла видимую модальную
  форму. На ней видны имя, группа, теги, proxy, режим браузера и пояснения;
  кнопки сохранения и отмены находятся внизу формы.
- **PASS — базовая Tab-навигация:** при открытии фокус визуально находился в
  «Название». `Tab` переместил его в «Папка / группа», а `Shift+Tab` вернул
  в «Название». Форма закрыта через Escape; профиль не сохранён, список остался
  пустым.
- **FAIL — дерево UI Automation не предоставляет семантику полей формы:**
  повторно снятое дерево главного окна и модального диалога перечисляет общие
  «панель»/«рисунок», но не именованные Edit/ComboBox/Button для полей и
  действий. Нельзя считать это подтверждением доступности для экранного
  диктора. Это наблюдение конкретного UIA-провайдера на этом ПК, не тест NVDA.
- **INCONCLUSIVE — ввод текста:** `type_text` с синтетическим именем не изменил
  видимое поле ни до, ни после обновления и активации окна. Сделана одна
  повторная попытка; дальнейшие клики/ввод прекращены по правилу тестирования.
  Это не доказывает дефект клавиатурного ввода самого приложения.
- **INCONCLUSIVE — Ctrl+N:** одна попытка горячей клавиши не открыла форму;
  отдельный повтор на новой сессии не выполнялся. Сама кнопка меню работает.

## Не проверено

NVDA/Narrator и чтение меток, создание/сохранение формы только клавиатурой,
масштаб Windows 100–200%, высокая контрастность, Windows 10, несколько DPI/
мониторов и прокрутка всей длинной формы. Не открывались страницы сайта; сетевые
и Chromium fingerprint-тесты не запускались.

Следующий небольшой этап: выяснить, может ли связка Tk 8.6.15 предоставить
полезное именованное UIA/MSAA-дерево без тяжёлого runtime-перехода; проверить
NVDA на одной копии текущей сборки; затем выбрать минимальный reviewable способ
экспонировать labels/roles/focus и добавить ручной/автоматический регрессионный
gate. Не менять Tk DLL и не объявлять доступность до повторной проверки EXE.
