## Цель и границы

Довести ограниченный набор улучшений лёгкого локального менеджера до проверенного portable ZIP, публичного скачивания и согласованного обновления существующего сайта. Не превращать этот цикл в переписывание Chromium или бесконечную реализацию всех идей исследования.

Основания: [MARKET_RESEARCH.md](MARKET_RESEARCH.md), [RESEARCH_BACKLOG.csv](RESEARCH_BACKLOG.csv), аудит фактического кода и проверяемые пользовательские сценарии. Рыночные заявления поставщиков не считаются доказательством их технической реализации; наш список не обещает равенство с антидетект-ядрами конкурентов.

## Подтверждённая промежуточная проверка

На source-freeze checkpoint пройдены **44 core tests, 7 Tk checks, 13 release-tool checks и source self-test**. Это результаты исходников/инструментария на текущем хосте, а не доказательство работы будущего ZIP или публичной ссылки. Любая поздняя правка требует повторения затронутых проверок.

Единственная валидируемая Windows-среда этого цикла — **Windows 11 x64 build 26200**. Windows 10, ARM64, x86 и другой чистый компьютер не становятся проверенными по косвенным признакам. Preview не подписан.

## Конечные gates

1. Заморозить код и packaged docs; убедиться, что release-version.json, changelog и ограничения согласованы.
2. Прогнать source/tooling gates, затем clean build из allowlist. Не собирать поверх пользовательского portable Data.
3. Проверить ZIP inventory, runtime licenses, source provenance, отсутствие секретов/Data и точный SHA-256.
4. Распаковать фактический ZIP в отдельный тестовый каталог; packaged self-test, ручной GUI, реальный Chrome/Edge, persistence, backup/restore, proxy error paths, безопасный выход, темы/клавиатура/прокрутка.
5. Измерить производительность с методом и средой, не обещая универсальную скорость. Исправить release-blocking P0/P1 и повторить затронутые проверки.
6. Проверить обновление через новую папку и приватный pre-copy Data; сохранить старый portable целиком для отката.
7. Опубликовать только разрешённый бинарный artifact и checksum; заново скачать публичный ZIP и сравнить bytes/hash с проверенным кандидатом.
8. Обновить существующий официальный сайт https://nevision-win.mail782861.chatgpt.site/ и changelog; проверить ссылки, версию, hash, размер, UTF-8, темы и адаптивность.
9. Зафиксировать фактические результаты и известные ограничения. Завершить goal только после artifact + download + website gates, а не по завершении кодинга.

Полная процедура: [RELEASE_CHECKLIST.md](../RELEASE_CHECKLIST.md). Источники и лицензия приложения пока остаются приватными; публичная бинарная поставка разрешена владельцем. Не создавать фиктивный GitHub Releases URL.

## Что сознательно отложено

- Fingerprint-patched Chromium/core fork: отдельный инженерный продукт с постоянными security updates, лицензированием и проверками согласованности отпечатка. Подмена нескольких JS-полей не считается антидетект-ядром.
- Собственный authenticated proxy broker и полная проверка HTTP CONNECT/SOCKS5/auth/exit IP: отдельный сетевой и security scope; текущая диагностика только TCP.
- Cloud sync, роли/команды, облачный vault и серверная инфраструктура: противоречат local-first масштабу выбранного цикла.
- RPA, массовая автоматизация аккаунтов, marketplace расширений, встроенные SDK и встроенный браузерный runtime: не нужны для проверки portable менеджера.
- Автоматическое обновление/самозамена EXE: сначала подписанная доставка, trust model, атомарность и безопасный rollback.
- Зашифрованные переносимые backups: полезный будущий кандидат, но требует формата, key derivation, восстановления ключей и migration tests. Сейчас ZIP явно обозначен незашифрованным.
- Полный UI корзины, расширенный импорт cookies и cross-PC secret migration: отдельные решения, без обещания переносимости DPAPI/App-Bound данных.
- Автоустановка расширений или устаревшие Chrome injection flags: нативный менеджер и явный выбор пользователя остаются безопасной минимальной границей.

## Критерии остановки

Успех: проверенный конечный portable ZIP доступен публично; повторно скачанный ZIP совпадает по SHA-256; сайт и changelog описывают именно его; нет известного необработанного P0/P1 в выбранном цикле; ограничения и проверенная платформа явно указаны.

Блокер: публикация/доступ/недостающая авторизация не могут быть завершены безопасно — сообщить конкретный blocker и сохранить проверенную сборку, не объявляя цикл завершённым. Не расширять полномочия до публикации исходников или пользовательских данных.

Остальные идеи сохраняются в backlog и не удерживают этот цикл открытым бесконечно. «Работает идеально» не является проверяемым критерием; вместо него — воспроизводимые результаты и честно перечисленные непроверенные среды.
